# 4G 总线注入：可写地址清单与风险分级

> 数据来源：`W系列485通信协议_V2.4.xlsx`（保持寄存器表）+ `Models/RegisterMap.cs`（属性判定）+ `MainForm.RegisterTable.cs`（WriteRules 实际可写白名单）+ `4G串口.txt`（4G 实际轮询区间）。
> 本文只做离线分析，未修改任何主程序代码。

## 一、总量

| 分类 | 数量 | 策略 |
|---|---|---|
| A 常规参数 | 37 | 可直接写 |
| B 运行相关 | 72 | 二次确认 |
| C 高危/专属 | 30 | 默认禁用，需手动解锁 |
| 合计（Excel 保持寄存器，已剔除预留项） | 139 | |

代码 `WriteRules` 实际开放写入的地址：**82** 个（2026-09-29 新增 40701~40703 热水器段）。
另有 **40107（同步时间，40107~40110 共 4 寄存器 64 位 UNIX 时间戳）** 走独立写入流程（0x10 整段写），不进入 `WriteRules` 单值校验，实际可写地址合计 **83** 个。
另外：`RegisterMap.GetAccess()` 已按协议**逐段对齐读写属性**——常用段 40001~40099 读写、常用只写段 40101~40199 只写、服务密码 40201~40299 / 工厂密码 40301~40399 / 单板产测密码 40401~40499 / 读写信息段 40501~40599 / 4G_OTA 40601~40699 / 用户应用层 RAM 40701~40799 / Flash 持久化 40801~40899 均为**读写**（协议原文标注即"读写命令段"）；其中产测/身份/OTA/Flash 段写入前会弹**高危二次确认**（`RegisterMap.IsHighRiskWriteSegment`）。风盘 41001~41201、地暖 42001~42100、MixPad 43001~43006 虽为读写，但归属各从机设备（0x91~0x9F / 0xA1~0xAF / 0x51~0x5F），PC 连热泵地址时以只读展示并标注所属设备。

**2026-09-29 修订**：
- 属性对齐：40401~40499、40501~40599、40601~40699、40801~40899 由"软件层只读"改回协议标注的**读写**，写入前弹高危确认。
- 外机-4G 风盘模板由"只列风盘1"改为 **15 台全建（n=1~15 → 内机 0x91~0x9F）**，按 21017 在线位图决定显示与轮询：未检测到的分组隐藏（可用"显示未检测到的风盘/分集水器"开关强制显示），在线的自动展开并加入轮询；分集水器（21016）同规则。
- 新增轮询块：`40401`（产测标志 2 寄存器）、`40501`（读写信息段 27 寄存器，含 IMEI/激活/MD5/单机并联模式）。
- 风盘模板显示按协议解码：温度 ÷10、型号枚举、故障码 BIT0~BIT9、功能集 BIT0~BIT6；硬件/软件版本号按 2 寄存器合成显示。

**2026-09-29 复审修正（真机 COM2 / MS-W300 验证）**：
- 轮询补齐 `40851~40858`（原只读 4 个寄存器，滤网清洁时间恒为 `--`）；外机-4G 区 `20060~20080`、`21001~21017` 经真机确认可用 **0x04** 读取，已加入轮询。
- 修复只读行写入漏洞：41001~41201 / 42001~42100 / 43001~43006 落在 40001~49999，`GetAccess` 会判为读写，误点会向热泵总线下发写命令，现按行属性拦截。
- 修复 40701 显示精度：传输值=实际值×100，应按两位小数显示（6500 → 65.00℃）。

## 二、从协议文档核对到的关键事实（对方案有直接影响）

| 项 | 协议规定 | 对注入方案的影响 |
|---|---|---|
| 串口参数 | RS485，9600，8，无校验，1 停止位 | 已确定，无需探测 |
| 请求帧 | 从机地址(0xF1~0xF4) + **主机地址(1B)** + 功能码 + 寄存器地址(2B) + 数量(2B) + CRC | **主机地址可选 0x51~0x5F**，PC 应取一个未占用的（如 0x5F），便于在抓包里区分"谁发的" |
| 响应帧 | 从机地址 + **响应标识 0xFF** + 功能码 + 寄存器地址 + 字节数 + 数据 + CRC | 响应帧不回显主机地址，无法从应答区分主站 |
| 帧边界 | 字节间隔 >3 ms 视为新帧 | 静默窗口判据远大于 3 ms 即可 |
| 从机应答 | 收到请求后 6~40 ms 内发出 | 写帧应答等待 100 ms 足够 |
| 主机时序 | 收到应答后间隔 ≥20 ms 才能发下一帧；超时 100 ms 重发，最多 3 次 | **PC 撞车会让 4G 触发重发**，总线负载翻倍，必须避免 |
| 广播/组播 | 广播 0x00、组播 0xF0，仅允许 0x06/0x10，无需应答 | 注入时不要用广播，否则拿不到应答、无法确认 |
| 写计数器 | 只读寄存器 **30110 = 4G 模块写保持寄存器累加数** | **可用来判断平台是否刚下发过写命令**，是"禁止注入"判据的最佳信号 |

## 四、结论要点

1. **默认可注入白名单 = A 类 37 个**：其中 13 个落在 4G 轮询区间内（**写完不用自己发读帧，等 4G 下一轮轮询即可回读验证**）；其余 24 个 4G 不读，写完必须自己补一帧 0x03 读回确认，会额外占用总线。
2. **4G 实际轮询的保持寄存器区间**（来自抓包，决定"免费回读"的范围）：

   `40001~40010`, `40105~40105`, `40201~40239`, `40301~40324`, `40501~40510`, `40519~40527`, `40701~40703`, `40801~40802`, `40851~40854`

3. **只写段 40101~40199 无法回读验证**（软件里显示"—"），只能靠应答帧是否异常判断；其中 40102/40105/40107/40111 是 **4G 专属**（天气、时间、通信中断标志），PC 写了也会被 4G 周期性覆盖，应直接禁写。
4. **整段禁写**：产测 40401~40499、IMEI/激活 40501~40599、OTA 40601~40699、Flash 统计 40801。
5. **主机地址**：抓包实测总线上的主机地址只有 `0x51`（852 帧全是它，即 4G 模块）。协议允许 0x51~0x5F，PC 建议固定用 **`0x5F`**，这样监听日志里一眼能分出"这条是 PC 发的"。
6. **建议的注入前置判据（三条同时满足才发）**：① 总线静默 ≥50 ms（远大于协议的 3 ms 帧边界）；② 本轮询周期内只读寄存器 **30110（4G 写保持寄存器累加数）未变化**，说明云平台这会儿没在下发写命令；③ 上一帧不是 4G 刚发出的请求（避免撞上它 100 ms 超时重发的窗口）。
7. **写失败禁止自动重试**：40101 解除报警、40106 恢复出厂这类命令，重试一次就多执行一次。
